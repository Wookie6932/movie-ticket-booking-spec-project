# Prototype and validation plan

1. Review the initial specification and list unverified business decisions (R1-R20).
2. Review three competitors using their public documentation; distinguish published flows from observed usability (R5, R9, R12, R14).
3. Check seat integrity, hosted-payment options for a future version, and accessibility feasibility (R7-R11, R18-R20).
4. Create a paper prototype with browse, sign-in, seats, review, confirmation, cancellation and administrator states. Use fake data and no real transactions (R1-R20).
5. Inspect prototype wording and state transitions; make traceable desk-review revisions.
6. Ask current-process, pain-point and desired-improvement questions. Run the same tasks with at least two other people; record actions and exact remarks separately from interpretation.
7. Revisit every specification section, log evidence and changes, publish the Markdown file on GitHub Pages and verify the exact URL.
8. Replace pending findings and export the final submission PDF only after real feedback is incorporated.

Plan review: the sequence preserves a draft before prototyping, isolates personal work and makes evidence gaps explicit. Owner sign-off remains pending.
